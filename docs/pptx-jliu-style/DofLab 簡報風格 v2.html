DofLab WORKSHOP FEATURE
A BRIDGE FROM CODE TO COLOUR

演算法不冷，
色彩不軟。

給設計人

每一個你按下「自動排版」的按鈕，背後都有一條 1960 年代被數學家寫下的演算法。它沒有要把你的工作搶走，它在等你下命令。

學會看懂程式，就像學會看懂一張色票——你不用會調，但你會知道為什麼這兩個顏色擺一起不好看。

給工程人

色彩不是裝飾，是一種訊息通道。當你的 dashboard 把錯誤標成橘色而不是紅色，使用者的腦會把警報程度自動下調 30%。

學會看懂色彩，就像學會看懂變數命名——你不用會調，但你會知道為什麼這個介面用起來總是有點不對勁。

01 · FOCUS

把自動化，
留給人。

DofLab 做的不是「拿掉人」的自動化，而是「把繁瑣留給機器、把判斷留給人」的自動化。

這個分界不在技術，在設計選擇。我們花最多時間在這條線該畫在哪裡。

我們不接「能不能取代 OOO」的合作；我們接「能不能讓 OOO 做更重要的事」的合作。

▸ FOUR ARGUMENTS

我會
論證四件事。

01
「準確」不是真理
當系統說 92%，那 8% 不是雜訊——是它故意藏起來的東西。
02
「流暢」不是理解
會說出口的，不一定知道自己說了什麼。
03
「方便」不是進步
我們把太多選擇外包給系統，最後忘了自己會選。
04
「誠實」是新時代的精度
下一代系統的競爭，會在「敢說不知道」這件事上分勝負。
DOFLAB / J. LIU END OF ROADMAP
● ARGUMENT 03 / CONVENIENCE P.24 / 31
▸ ARGUMENT 03

「方便」
不是
進步。

RULE / 01

每一鍵省下的決定

都從你身上拿走了一次練習。一年下來，你少做了大約三千次判斷。

RULE / 02

不是不該方便

是要意識到，方便從來不是中性的——它在重新塑造你的習慣。

RULE / 03

設計者的責任

把「保留判斷」做成預設，把「自動化」做成可選；而不是反過來。

DOFLAB / J. LIU P.24
● POSITION / WHERE I STAND P.25 / 31
▸ WHERE I STAND

三句
大白話
當結論。

POS / 01

準確 ≠ 真理

誠實的系統，會告訴你它的不確定來自哪裡，而不是把它平均掉。

POS / 02

流暢 ≠ 理解

下次當你的助手「答得很好」時，順手問一句：你怎麼知道的？

POS / 03

方便 ≠ 進步

進步是讓人保有「我可以選」的權利，而不是替他先選了。
